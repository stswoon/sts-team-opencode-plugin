# multi-impl2

Оркестратор непрерывного цикла. Production-код сам не пишешь. Всё, что делает одна волна (выбор сторей, Dev → QA → Lead, гейты, решения `D…`, статусы, коммиты), — из skill **`multi-impl`**; `multi-impl2` его не дублирует, а повторяет, пока проходит гейт продолжения.

```
multi-impl2
  └─ волна N ───────────── skill multi-impl (выбор сторей → dev → qa → lead → коммит)
       └─ гейт продолжения
            ├─ пройден и есть готовые стори → волна N+1 …
            └─ стоп → итоговая сводка по всем волнам
```

Это режим «все волны» из `multi-impl` плюс явный гейт и суммарный отчёт: пользователю не нужно после каждой волны писать «продолжай».

## Одна волна

1. Загрузи skill `multi-impl` (tool `skill`); если недоступен — прочитай `../multi-impl/SKILL.md` и следуй файлу. Правила волны — оттуда, не переизобретай их.
2. Выполни **одну волну** по `multi-impl`: раздел «Выбор сторей» (как «все волны», п. 5) → для каждой стори раздел «Цикл одной стори» (Dev → QA → Lead) → после каждого `LEAD_PASS` статус `сделано` и коммит. Раздел «После волны» `multi-impl` не исполняй здесь — к нему вернёшься в итоге.
3. Между волнами — одна строка пользователю: номер волны, закрытые стори с хешами, что берёшь дальше. Полный отчёт — один раз в конце.

Пользователь назвал ID — волны идут только по этому набору (правило 2 `multi-impl`), чужие стори не подхватывай. Без ID — автоматически все готовые.

## Гейт продолжения

Следующую волну бери, только если после завершённой волны всё выполнено:

- **есть готовые стори** — `не сделано`, все зависимости `сделано`, папки не конфликтуют;
- **нет блокеров** — ни одна стори волны не осталась без `сделано` (лимит петель `multi-impl`, вынесенные пользователю замечания), нет нестыковки или расхождения со спекой, ждущих ответа, все `D…` записаны в `.cursor/artifacts/decisions.md`;
- **волна дала прогресс** — хотя бы одна стори стала `сделано`, дерево по правилам `multi-impl` чистое (закрытые стори и их артефакты закоммичены).

Иначе — **стоп**: в следующую волну не уходишь, даже если готовые стори есть. Не переделывай сверх лимита уже проваленные стори и не «добивай» волну.

## Итог

Остановился — отдай полный отчёт за все волны запуска (структура — «После волны» `multi-impl`, но суммарно):

- закрытые стори всех волн с хешами коммитов (`Sxx: <краткое> (LEAD_PASS)`);
- оставшиеся `не сделано`: готовые к следующему запуску и заблокированные (чем: зависимости, папки, решения);
- блокеры, из-за которых цикл остановлен;
- сводка решений `D…` (что решено и почему, альтернативы, стори, файлы) и путь к `.cursor/artifacts/decisions.md`; решений не было — сказать прямо;
- приглашение «поменяй D<N> на вариант …» и что открывать руками (`npm run dev`).

Закрытые волны не откатываются: их коммиты и статусы `сделано` остаются.

## Пока цикл идёт

Пользователь ответил на вопрос или просит поменять `D<N>` — сначала выполни «Изменение принятых решений» `multi-impl` (правка журнала, переделка затронутых стори до `LEAD_PASS`), и только потом снова решай гейт: ответ снимает стоп-фактор.

## Не делать

- Не дублировать `multi-impl` (промпты ролей, артефакты, статусы, решения, коммиты) — только ссылаться.
- Не менять `multi-impl` из этого скила: цикл живёт здесь, поведение волны — там.
- Не начинать волну, не пройдя гейт продолжения.
- Не уходить в следующую волну с незакрытой или незакоммиченной стори.
- Не подхватывать чужие стори, когда пользователь назвал ID.
- Не продолжать после стопа по блокеру, пока блокер не снят (пользователем или новым решением).

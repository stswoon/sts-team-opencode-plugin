## Что проверить

1. Матрица: строка на каждый acceptance scenario этой истории, каждый FR / SC, который она закрывает, и каждое решение
   `D…`. Для `FOUNDATION` / `POLISH` / `CONV` вместо acceptance scenarios бери задачи фазы, требования `plan.md` и
   инварианты `spec.md`.
2. Смысл, а не только тесты: поведение соответствует `spec.md`; цифры и формулы совпадают; нет незапрошенного поведения
   и фичи вне scope.
3. `plan.md` и конституция `.specify/memory/constitution.md` не нарушены. Если конституция — пустой шаблон, пропусти и
   скажи.
4. QA и Lead действительно покрыли свои пункты свидетельствами; не принимай формальный отчёт.
5. Расхождения со `spec.md` / `docs/spec.md` / конституцией: не решай молча, верни оркестратору свидетельства, варианты,
   рекомендацию.
6. Пробелы, которые не входят в scope этой истории и относятся к фиче целиком, — запиши в раздел «Вне scope работы» с
   пометкой «для /speckit.converge»; не вали историю за них.

## Сдача

Каждый прогон сохраняй в `specs/<feature>/artifacts/acceptance-<item>.md`; не перезаписывай артефакты других работ:

```markdown
# Acceptance <item>

## Решение

ANALYST_PASS / ANALYST_FAIL

## Матрица приёмки

| ID / пункт | Требование | Свидетельство | Результат |

## Расхождения со спекой

## Вне scope работы

## Следующий шаг для Dev
```

`ANALYST_FAIL` — есть расхождение, незакрытый FR/SC/acceptance scenario или решение `D…`, либо свидетельство QA/Lead
недостаточно. `ANALYST_PASS` — матрица закрыта, расхождений нет. Не коммить. Не меняй код, тесты, статус работы и
`tasks.md`.

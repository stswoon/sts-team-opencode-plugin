# stsTeamPlan (Spec Kit tasks slicing)

Оркестратор. Сам `tasks.md` не пишешь — запускаешь субагента **analyst** (агент регистрируется плагином) с промптом
[prompt-tasks.md](prompt-tasks.md). Код и `spec.md` / `plan.md` не меняешь.

```
tasks.md → analyst → статусы + папки + зависимости + ресурсы + фронт поставки
```

Дальше реализацию делает skill `stsTeamImpl` по работам со статусом `OPEN` или `IN_PROGRESS`.

## Вход

`FEATURE_DIR` — путь `specs/NNN-*`:

1. из аргумента `/stsTeamPlan specs/NNN-...` или `FEATURE_DIR`, переданного из `/speckit.tasks`;
2. иначе — из `.specify/feature.json`;
3. иначе — запусти `setup-tasks.cmd -Json` (Windows; на других ОС — `.ps1`/`.sh`) из корня проекта и разбери JSON.

Обязательны `spec.md`, `plan.md`, `tasks.md`. Чего-то нет — стоп и назови команду: `/speckit.specify`,
`/speckit.plan` или `/speckit.tasks`.

## Шаги

1. Прочитай `AGENTS.md`, `spec.md`, `plan.md`, `tasks.md` и доступные `research.md`, `data-model.md`, `contracts/`,
   `quickstart.md`, конституцию. Это контекст для промпта, не подменяй аналитика.
2. Критичный пробел (неясно, какие истории параллелить, что считать эксклюзивным путём) — вопрос пользователю **до**
   `subagent` в формате ниже.
3. Запусти **один** `subagent`:
   - `agent`: `analyst`
   - `description`: Spec Kit tasks slicing
   - `prompt`: текст из [prompt-tasks.md](prompt-tasks.md) с подставленными `FEATURE_DIR`, `{{N_SLOTS}}`, путями.
4. Если агент вернул открытые вопросы, допущения или нестыковки — не принимай их молча и не выбирай за пользователя.
   Вынеси каждый вопросом в формате ниже, дождись ответов и только потом продолжи того же субагента (`subagent` с его
   `sessionID`) с этими ответами. Не выдумывай требования.
5. Проверь гейт (сам, без нового агента):
   - у каждой фазы `tasks.md` есть `**Статус:**` только из `OPEN` / `IN_PROGRESS` / `DONE` / `CANCELLED`;
   - у каждой фазы есть `**Дорожка**`, `**Параллель**`, `**Зависит от**`, `**Разблокирует**`,
     `**Папки (только эти)**`, `**Ресурсы**`, `**Приёмка**`;
   - есть блок `**Эксклюзивные пути:**` и `## Фронт поставки` с волнами, шириной и узким местом;
   - ID, описания, `[USn]` и порядок задач не изменились (сравни список задач до и после);
   - у параллельных работ нет общих записываемых путей и общих ресурсов `ui` / `db` / `build` / `codegen`;
   - ни одно допущение/нестыковка не остались без ответа пользователя.
   Пробел гейта — продолжи того же analyst'а (`subagent` с его `sessionID`) с перечнем, что дописать; это не вопрос
   пользователю и не повод отдавать работы в `stsTeamImpl`.
6. Пользователю: что добавлено в `tasks.md`, таблица работ со статусами, ширина фронта, узкое место, какие работы готовы к
   `/speckit.implement`. Не коммить.

## Вопросы пользователю

Спрашивай при **нестыковке** (требования задачи противоречат друг другу, спеке, плану, tasks или фактам репо) или
**допущении**, которое не снимается спекой, планом, tasks, кодом и тестами. Что снимается кодом и тестами — снимай сам,
не спрашивай.

Вопрос должен быть понятен без истории чата. Обязательные части:

1. **Где** — `spec.md:FR-001`, `plan.md`, `tasks.md:T012` или `файл:строка`.
2. **Что там** — цитата или факт из источника, 1–2 строки.
3. **Что не сходится** — конкретное противоречие или пробел; какое поведение/параллельность остались неопределёнными.
4. **Что зависит от ответа** — какие пункты tasks/плана изменятся или без ответа заблокированы.
5. **Варианты** (2–4) — для каждого: что это значит для продукта, спеки, плана и тестов, плюсы и минусы. Первый —
   рекомендованный: «(Recommended)» и одна фраза почему.
6. Инструмент `question`: свободный ответ («Type your own answer») не отключай и не добавляй свой вариант «Другое».

Все вопросы одного захода — одним сообщением, с нумерацией Q1, Q2, … Повторно уже отвеченное не спрашивай.

## Не делать

- Не запускать `dev`, `qa`, `lead`.
- Не писать код проекта и не менять `spec.md` / `plan.md`.
- Не переписывать ID, описания, `[USn]` и порядок задач; ошибочный `[P]` можно убрать с пометкой в отчёте.
- Не менять границы историй молча: это вопрос пользователю.
- Не ставить `DONE` и не менять `IN_PROGRESS` — это делает `stsTeamImpl`; `OPEN` — только для новых фаз.
- Не принимать допущения или нестыковки analyst'а молча — даже «не блокеры».
- Не принимать план без блока «Фронт поставки»; пробелы закрывает продолжение analyst'а, а не молчание.
- Не коммитить.

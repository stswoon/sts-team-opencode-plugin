# Промпт для subagent / analyst (нарезка tasks.md)

Роль задана агентом `analyst` (регистрируется плагином). Подставь поля. Субагент не видит историю родительского чата.

---

Режим: нарезка `tasks.md`.

Фича: `{{FEATURE_DIR}}`
Файлы: `{{SPEC_PATH}}`, `{{PLAN_PATH}}`, `{{TASKS_PATH}}`
Слотов в работе: {{N_SLOTS}}

Прочитай `AGENTS.md`, `spec.md`, `plan.md`, `tasks.md`, а также `research.md`, `data-model.md`, `contracts/`, `quickstart.md`
и конституцию, если они есть. Выполни пасс параллельности для `tasks.md`. Формат метаданных — из системного промпта
analyst (`tasks-metadata-template.md`).

## Что сделать

1. **Работы.** Разбей фазы на работы: `FOUNDATION` (Phase 1 Setup + Phase 2 Foundational), `US1..USn` (фазы историй),
   `POLISH`, `CONV1..n` (Convergence). Для каждой выпиши: задачи, пути файлов, тесты, acceptance scenario / FR / SC,
   ресурсы (`ui`, `db`, `build`, `codegen`, `none`).
2. **Пути.** Собери `**Папки (только эти)**` по фактическим путям задач. Общие записываемые файлы и папки — в
   `**Эксклюзивные пути:**` (контракты, миграции, локали, корневые манифесты/lockfile, entry points).
3. **Зависимости.** Граф **жёстких** зависимостей: общий записываемый файл/папка, контракт (тип/API/JSON) или данные.
   Приоритет, «логичный порядок» и удобство ревью — не причина. `FOUNDATION` → все US; `POLISH` → после всех US;
   `CONV` → после всех не-Convergence фаз. Лишние зависимости убери.
4. **Волны.** Посчитай жадный план при {{N_SLOTS}} слотах: ширина каждой волны, критический путь. Учти ресурсы: работы с
   `ui` / `db` / `build` / `codegen` не идут одновременно. Узкое место — цепочка или общий путь/ресурс, который
   сериализует фронт.
5. **Расширение фронта.** По возрастанию цены: снять нежёсткую зависимость; развести общий файл (правку отдать более
   ранней работе); дробление по непересекающимся папкам. Не меняй смысл, scope и границы историй. Если для
   параллельности нужно менять `spec.md` / `plan.md` / границы историй — верни это вопросом пользователю, не делай молча.
6. **Запись.** В `tasks.md`:
   - добавь/обнови `**Статус:**` (новые фазы — `OPEN`; существующие `DONE` / `IN_PROGRESS` не сбрасывай);
   - добавь `**Дорожка**`, `**Параллель**`, `**Зависит от**`, `**Разблокирует**`, `**Папки (только эти)**`,
     `**Ресурсы**`, `**Приёмка**`, `**Не делать**`;
   - добавь `**Эксклюзивные пути:**` и `## Фронт поставки` с волнами, шириной и узким местом.
7. **Самопроверка.** У каждой фазы есть статус и метаданные; у параллельных работ нет общих путей и ресурсов; ID,
   описания, `[USn]` и порядок задач не изменены; фронт посчитан при {{N_SLOTS}} слотах. Ошибочный `[P]` можно убрать —
   отметь это в ответе.

## Выход оркестратору

1. Какие фазы/work items обновлены.
2. Ширина фронта, волны, узкое место и что пробовал, если ширина меньше {{N_SLOTS}}.
3. Какие `[P]` убрал и почему.
4. Открытые вопросы — подробные, каждый: где (`файл:строка`), что там, что не сходится, что зависит от ответа, 2–4
   варианта с последствиями и рекомендацией — или «нет».

Не коммить. Не меняй `spec.md` и `plan.md`. Не ставь `DONE` / `IN_PROGRESS`.
